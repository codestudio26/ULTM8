# Staging runbook: Render + Supabase + Vercel

| Piece | Platform |
|---|---|
| `apps/api` | Render web service (free), from `render.yaml` |
| Redis | Render Key Value (free) |
| Postgres 16 | Supabase (free) |
| `apps/school-portal` | Vercel project #1 |
| `apps/platform-admin` | Vercel project #2 |

Every secret is typed into the provider's own dashboard. Never commit one, and
never paste one into a chat.

## 1. Supabase (Postgres)
1. Create a project (or reuse the existing staging one). Pick a region close to
   the Render region you'll use. Save the database password somewhere safe.
2. **Project Settings → Database → Connection string → "Session pooler"**
   (port 5432). This is `DATABASE_URL`. It looks like
   `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`.
   Don't use the direct `db.<ref>.supabase.co` host: it is IPv6-only, and
   Render's build machines can't reach it.
3. Make the six scoped-role URLs from the same string. Swap the user to
   `<role>.<ref>`, set a **new strong password per role** (you choose it;
   percent-encode `@ : / ? #`), and append `?connection_limit=2`:
   - `DATABASE_URL_APP` → `ultm8_app.<ref>`
   - `DATABASE_URL_AUTH` → `ultm8_auth.<ref>`
   - `DATABASE_URL_JOBS` → `ultm8_jobs.<ref>`
   - `DATABASE_URL_DISCOVERY` → `ultm8_discovery.<ref>`
   - `DATABASE_URL_PLATFORM_ADMIN` → `ultm8_platform_admin.<ref>`
   - `DATABASE_URL_GRADING_ERASURE` → `ultm8_grading_erasure.<ref>`

   The roles don't exist yet. The first Render build creates them (migrations)
   and sets these passwords on them (`apps/api/scripts/rotate-role-passwords.js`).

> One migration (`20260904000000_fix_rolegrant_rls_recursion`) runs
> `CREATE ROLE ultm8_rls_helper NOLOGIN BYPASSRLS`. That needs Supabase's
> `postgres` user to hold BYPASSRLS, which it did on the earlier track-b
> staging deploy. If the build log fails there, stop and report it. Don't edit
> the migration.

## 2. Render (API + Redis)
1. Render → **New + → Blueprint** → this repo → branch `master` (or the branch
   under test). Render reads `render.yaml` and creates `ultm8-redis` and
   `ultm8-api`.
2. Render prompts for every `sync: false` value:
   - **Required:** `DATABASE_URL`, the six `DATABASE_URL_*` values,
     `CORS_ALLOWED_ORIGINS`, and `PORTAL_BASE_URL`. For the last two, put a
     placeholder such as `https://placeholder.invalid` for now; you'll set the
     real values after step 3.
   - **Vendors** (Stripe *test* keys, Twilio, Postmark, Cognito, R2, FCM,
     Stream): leave blank until each account exists. The API boots without
     them and logs which ones are missing.
   - The signing secrets are generated by Render (`generateValue`), so you
     don't type them.
3. The build runs: install → prisma generate → **migrate deploy** → **rotate
   role passwords** → build. Then it starts with `NODE_ENV=production`, which
   **refuses to boot** if any required value is missing or unsafe. The deploy
   log lists exactly which one.
4. Check `https://<service>.onrender.com/v1/health` → `{"status":"ok","db":"ok","redis":"ok"}`.
   Check `/v1/docs` too.

> Free Render instances sleep after about 15 minutes idle. The BullMQ
> schedulers (membership expiry, no-shows, class generation, ...) run inside
> the API process, so **they stop while it sleeps**. This is acceptable for
> staging. Production needs a paid, always-on instance.

## 3. Vercel (both portals)
Do this twice, once per app:

| | school-portal | platform-admin |
|---|---|---|
| Root Directory | `apps/school-portal` | `apps/platform-admin` |
| Env (Production + Preview) | `VITE_API_BASE_URL=https://<api>.onrender.com` | `VITE_API_BASE_URL=…` plus `VITE_COGNITO_DOMAIN`, `VITE_COGNITO_CLIENT_ID`, `VITE_COGNITO_REDIRECT_URI=https://<admin>.vercel.app/login` |

Vercel → Add New → Project → import the repo → set the Root Directory. Build
settings come from each app's `vercel.json`: install from the repo root, turbo
build, `dist`, and SPA rewrites. `VITE_*` values are baked in at build time, so
**redeploy** after changing them.

Then go back to Render → `ultm8-api` → Environment and set:
- `CORS_ALLOWED_ORIGINS=https://<portal>.vercel.app,https://<admin>.vercel.app`
  (exact origins, no trailing slash)
- `PORTAL_BASE_URL=https://<portal>.vercel.app`

## 4. First accounts
- **Platform Admin:** create the user in the Cognito pool (MFA required). Then
  run `scripts/bootstrap-admin-user.ts` with that user's `sub` (see the
  script's header). Run it from a machine with `DATABASE_URL` set.
- **Demo data (optional, staging only):** the dev seeds refuse non-local
  databases. To seed staging on purpose, set
  `ULTM8_ALLOW_DEV_SEED_HOST=<pooler host>` for that one command. **Never do
  this on production.** The seeds create logins with passcode `123456`.

## 5. Verify
- `/v1/health` returns 200. Both portals load, sign in, and make API calls with
  no CORS errors in the browser console.
- Each scoped role really is in use: in the Supabase SQL editor, run
  `select usename, count(*) from pg_stat_activity group by 1`. You should see
  `ultm8_*` users, not just `postgres`.
- Smoke flow: register → create school/branch → invite staff → class →
  booking → QR check-in → waiver → Platform Admin login.
